## Two traps this run set off — both worth knowing before the next A/B

1. **The MoE run's own `/tmp/ab-drain-moe.summary` is untrustworthy and was
   discarded.** It printed `prefill_med 0.00` for both arms with the *MAD*
   column carrying the true median (712.750 / 88.130) — the exact signature of
   the old `med()`. Cause: the `med()` fix was written to `tests/bench_ab.sh` at
   **18:17:33, while that A/B was still running**, and a `bash` process keeps
   reading the script it launched. So the fix did not apply to that run's
   summary. Always check the script's mtime against the run's start before
   trusting a summary file.
2. **`med() = 0` is recognisable without any other tooling:** if `prefill_med`
   is `0.00` while its MAD column holds a plausible throughput number, you are
   looking at the broken code, because `mad_of(arr, n, 0)` degenerates into the
   median of the raw values. A real MAD is always small (0.1–10 t/s here).

Both arms are indistinguishable, which is the only possible outcome: the removed
block was gated on `q36_vk.prof_kernel`, so with no profiler env set the two
binaries cannot differ. The drain change is inert in production; it is profiling
hygiene at best, not a speed lever. See `../ab-hostdrain.md`.
