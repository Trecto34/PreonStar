QuarkStar Swift Qwen3.8-27B change log
======================================

2026-09-17

- Added Swift IQ4_XS and IQ3_XXS download targets and launchers for
  ukisai/Swift-Qwen3.8-27B-GGUF.
- Added bounded dense-weight caching, retained-prefix reuse, and recyclable
  stream buffers so IQ4_XS can run without the recurring OOM/SIGKILL path.
- Permanently deleted the unusably slow 14.6 GiB IQ4_XS file after validating
  that the smaller Swift IQ3_XXS tier was the practical choice on this BC-250.
- Resumed and completed Swift-Qwen3.8-27B-IQ3_XXS.gguf; final size 11.67 GiB.
- IQ3_XXS Vulkan inspection passed. Protected launcher smoke test returned
  READY at 39.92 tok/s prefill and 21.90 tok/s generation.
- q36-bench IQ3_XXS baseline at 1024 context: 180.27 tok/s prefill and
  23.01 tok/s generation with 8 greedy output tokens.
- q36-bench with three-position MTP: 175.21 tok/s prefill and 21.73 tok/s
  generation. MTP draft=1 is therefore the new Swift launcher default; draft=3
  remains available through Q36_SWIFT_MTP_DRAFT=3.
- Attention span 128 measured 23.80 tok/s at 1024 context but regressed to
  19.10 tok/s at 2048 versus 22.02 tok/s with span 512. It was not enabled.
- Local reference measurements: Qwen3.6 35B-A3B IQ2XXS reached 53.39 tok/s;
  Qwen3.8-27B IQ3_S reached 18.93 tok/s; bounded IQ4_XS reached 0.11 tok/s.
- A full resident IQ4_XS experiment allocated 14.6 GiB active GPU memory and
  triggered the global OOM killer, terminating Codex. That path was removed
  from the default launcher and the safe bounded profile was restored.
- Current commits include 936c9f1 (usable IQ3_XXS profile) and the follow-up
  performance work in the working branch.
- Added a Swift target profile under `karpathy/`; its inner/outer entrypoints
  now delegate to the authoritative persistent logic in `~/Karpathy`. The
  shared loops use this target's independent compatibility gate: Swift IQ3_XXS
  and the Qwen3.5/Qwen3.6 `qwen35moe` reference run sequentially before a
  candidate can be accepted, with separate executable checks and hard timeouts.
- Compatibility gate validation passed on the BC-250: Qwen3.5/Qwen3.6
  `qwen35moe` short CPU/Vulkan parity was `OK`, followed by Swift IQ3_XXS at
  177.84 prefill tok/s and 21.19 generation tok/s; no GPU process remained.
- Fixed Ctrl-C cleanup in the shared Karpathy orchestrator and target gate:
  active commands now run in dedicated process groups and are terminated
  together, preventing an orphaned `q36_test` from blocking the next pass.
- Reduced the shared meta-agent provider watchdog from 900 seconds to 180
  seconds per tier, with explicit fallback-stage output and a
  `KARPATHY_META_TIMEOUT` override, so cadence audits cannot appear hung for
  fifteen minutes before falling back.
- Added `KARPATHY_SKIP_META=1` to the shared orchestrator for an immediate inner
  pass when persistent cadence state would otherwise start the slower meta audit.
- Added a project-local direct DeepSeek provider in `opencode.json`, using the
  current `deepseek-flash` API model (DeepSeek V4.1 Flash) at the official
  OpenAI-compatible base URL. Credentials remain outside the repository through
  `DEEPSEEK_API_KEY` or `DEEPSEEK_API_KEY_FILE`.
- Added `KARPATHY_PROVIDER=deepseek` support to both Karpathy loops. Inner and
  outer runs use `deepseek-direct/deepseek-flash`, load the target OpenCode
  config explicitly, and stop on DeepSeek failure instead of silently changing
  providers.
- Added an outer-loop credential preflight; a missing DeepSeek key now exits
  before any compatibility or GPU process is launched.
- Fixed propagation of outer-loop preflight/failure exit statuses and updated
  the fallback regression fixture for the mandatory target compatibility gate.
- DeepSeek now loads `${HOME}/.config/deepseek/api-key` automatically with no
  per-session export required; explicit environment variables still override it.
- Target wrappers now select DeepSeek by default, so the persisted-key setup
  runs directly with `./karpathy/run_outer.sh`; `KARPATHY_PROVIDER=union`
  remains an explicit legacy override.
- Tightened the inner DeepSeek worker: the harness injects target/shared
  previous-attempt snapshots and requires a `LEDGER_CHECK` before source work.
  The direct model is capped at 32K context and 4096 output tokens, with a
  600-second default watchdog against open-ended exploratory passes.
- Failed or incomplete worker turns now skip the expensive compatibility gate;
  only a successful ledger-checked turn can consume GPU time on validation.
- Added Linux parent-death signals to the orchestrator and experiment worker so
  abrupt supervisor termination cannot leave an orphaned DeepSeek agent running.
- Added `--verbose`/`KARPATHY_VERBOSE=1` to both target loops, streaming the
  inner worker live while preserving its worker log.
- Closed and recorded interrupted experiment `20260917T120056-9e9fa702`: its
  lane-split `dense_iq3_xxs_mmq` candidate was bit-exact but regressed down
  projection by about 2.7%, and was terminated before its final report. The
  rejected mechanism is now recorded in the target AlreadyTried ledger.

2026-09-17: BC-250 vllm-mxfp4 transfer audit
- New branch experiment/radiance-transfer-bc250; separate dirty q36-opt checkout
  preserved. Added tests/benchmark_transfer.sh for serial, interrupt-safe,
  three-repetition Swift IQ3_XXS and Qwen3.6 IQ2_XXS benchmarking.
- Reverted all tested shader candidates: 512-thread add/RMS regressed Swift
  kernel 23.64 to 30.13 ms; packed sign handling regressed IQ3 decode 373.83
  to 407.97 ms; XOR-swizzled IQ3 MMQ regressed 940.28 to 1309.31 ms; direct
  MoE table reads gave no reproducible full-context Qwen3.6 gain.
- At context 1024 / generation 16, safe chunk sweep: Swift 64/128/256 =
  96.37/164.73/171.91 prefill tok/s; Qwen3.6 256/512/1024 =
  720.58/858.86/951.38. Existing safe defaults were best.
- Final unchanged-kernel three-run averages: Swift 172.41 prefill, 22.53
  decode tok/s; Qwen3.6 923.48 prefill, 88.01 decode tok/s. Accepted
  model-speed gain: 0% for both. Qwen CPU/Vulkan parity and Swift smoke passed.

2026-09-17 follow-up after throughput feedback:
- IQ3_XXS MMQ 256-token tile: 166.87 prefill tok/s; 64-token tile: 161.07,
  versus 172.41 baseline at context 1024. Both reverted.
- MTP draft depth 2: 23.28 generation tok/s versus 24.14 with depth 1 over
  128 tokens. No default change.
- Removing MMQ forced unrolling worsened 128-token kernel time about 940 to
  960 ms. Eight-row IQ3 decode matched baseline 24.14 tok/s, no gain.
  Both shader changes reverted; original build restored.
