WHY matmul_bf16 IS #1:
  ssm_alpha.weight and ssm_beta.weight (48 x 5120, ggml type bf16) are bf16 and
  NOT Hadamard-rotated, on all 48 recurrent layers. 2 dispatches x 48 layers =
  96 dispatches/token; 6240 total over 65 steps. 9528 ms / 6240 = 1.53 ms per
  dispatch.
  vulkan/matmul_bf16.comp was copied from matmul_f16.comp: ONE workgroup per
  output row (out_dim = 48), 64 threads, each thread runs in_dim = 5120
  iterations of fp64 FMA over bf16 loads. 48 workgroups x 64 threads = 3072
  threads on ~24 CUs; the reduction is fully serial and fp64-bound. This is the
  same slack the f16/f32 dense shaders have (their comment says they "see little
  runtime use: f32 matvecs run on the host"), but for this model they are 76% of
  all GPU time.
