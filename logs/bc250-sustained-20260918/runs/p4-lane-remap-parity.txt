row = r*4 + lane_row instead of lane_row*16 + r.

Bank-conflict accounting (say it in the right units):
  - LDS has 32 banks at DWORD (4-byte) granularity.
  - A load reads one f16vec2 = one DWORD, address word index
    addr = (row)*STRIDE + k, STRIDE = 17 DWORDs.
  - A wave is 64 lanes; lane_row = lane & 3, so per A-load instruction the
    four simultaneous addresses are the four lane_row bases (each requested
    by 16 lanes, which is a broadcast, not a conflict).
  - baseline rows lane_row*16 + r: lane_row bases are 0, 272, 544, 816 DWORDs;
    mod 32 -> 0, 16, 0, 16.  Two of the four distinct addresses share a bank,
    so the load serializes 2x.
  - P4 rows r*4 + lane_row: lane_row bases differ by 17 DWORDs -> 0, 17, 34, 51;
    mod 32 -> 0, 17, 2, 19, four distinct banks, no conflict.

NOTE: earlier drafts wrote "0/17/34/51 -> four distinct banks", which mixes
unreduced offsets with bank indices.  The bank indices are 0/17/2/19.
Pure relabeling: per-output reduction order (qb, slice, k) unchanged.
